## OVERVIEW

**${PROJECT_NAME}** is an open-hardware measurement board developed as part of **OPEN THRUST LAB**, a community-driven project building open-source test benches for drone motor characterization.

The board reads **NTC thermistors** to log temperatures on the test bench (for example motor, ESC and battery). Each NTC sits in a voltage divider with a bridge resistor; the divider voltages go through an RC input filter to an **Analog Devices AD7124-8**: a 24-bit sigma-delta ADC with 8 differential or 15 pseudo-differential inputs, a programmable gain amplifier, an internal reference, programmable excitation currents and an SPI interface to the host.

It follows the same tooling as its sister boards [OPEN_PHASE](https://github.com/foukouda/OPEN_PHASE) and [OPEN_WEIGHT](https://github.com/foukouda/OPEN_WEIGHT): KiCad 10, KDT hierarchical template, KiBot outputs generated by GitHub Actions, self-contained libraries.

## DESIGN DECISIONS

To decide before drawing the schematic, then to record in the sheet notes and in this README:

| # | Decision | Notes |
| --- | --- | --- |
| 1 | Number of NTC channels | Sets the AIN allocation and the connector count. |
| 2 | NTC part (resistance at 25 °C, B coefficient) and temperature range | Sets the bridge resistor value and the resolution in °C. |
| 3 | Bridge resistor: value, tolerance, temperature coefficient | Dominates the accuracy once the ADC is calibrated. |
| 4 | Reference: ratiometric or internal | Ratiometric: the dividers are supplied by the voltage used as ADC reference, so supply drift cancels out. |
| 5 | RC input filter and protection | Corner frequency against the chosen output data rate; ESD if the probes are on long cables. |
| 6 | Power: host supply voltage, AVDD regulator, IOVDD level | AVDD 2.7 V to 3.6 V. |
| 7 | Host connector and pinout | SPI, optional SYNC, supply, GND. |
| 8 | Board size and mounting | Fits the OPEN THRUST LAB test bench. |

## HOW TO USE

### Prerequisites

- **KiCad 10** (files are saved in KiCad 10 format and cannot be opened with KiCad 9 or earlier)
- Nothing else: every symbol, footprint and 3D model goes in `lib/` and is referenced relative to the project (`KIPRJMOD`, project-local `sym-lib-table` / `fp-lib-table`)
- **KiBot** for automated output generation, **Docker** recommended for local CI runs

### Generate outputs locally

```bash
./kibot_launch.sh               # default configuration
./kibot_launch.sh -v CHECKED    # specific variant
```

| Variant | Outputs | ERC/DRC | Typical use |
| --- | --- | --- | --- |
| `DRAFT` | Schematic only | — | Early design work (current CI setting) |
| `PRELIMINARY` | Schematic + PCB | — | Layout iterations |
| `CHECKED` | Full | ✓ enforced | Design review |
| `RELEASED` | Full | ✓ enforced | Tagged version releases |

## DEVELOPMENT WORKFLOW

This project uses a reproducible hardware workflow based on **KiCad 10**, **KiBot** and **GitHub Actions**.

The CI pipeline (`.github/workflows/ci.yaml`) runs KiBot on every push to `dev` or `main` and commits the generated outputs back ("Update Outputs" commits). **Always `git pull` after the CI has run, before editing the project again**, otherwise the regenerated files (`.kicad_pro`, BoM, netlist, README…) will conflict.

> ℹ️ `README.md` is **generated** by KiBot from `kibot_resources/templates/readme.txt`. Edit the template, not `README.md`, or your changes will be overwritten by the next CI run.

**Branch convention:** `dev` is the development branch; `main` only receives merges from `dev` and carries the release tags.

**Project metadata** (project name, board name, company, designer, logo, repository URL) is defined once in `kibot_yaml/kibot_main.yaml` (`definitions:` section) and propagated to title blocks, documents and this README.

**When the PCB has an outline and placed parts:** switch `kibot_variant` to `PRELIMINARY` in `ci.yaml` and uncomment the 3D renders at the top of `readme.txt`.

**Release a new hardware revision:**

1. On `dev`, fill the `[Unreleased]` section of [CHANGELOG.md](CHANGELOG.md).
2. Switch `kibot_variant` to `CHECKED` in `ci.yaml` once ERC and DRC are clean.
3. Merge `dev` into `main`: `git checkout main && git pull && git merge dev && git push`
4. Tag with a plain semantic version (**no `v` prefix**): `git tag 1.0.0 && git push origin 1.0.0`
5. Re-sync `dev`: `git checkout dev && git merge main`
